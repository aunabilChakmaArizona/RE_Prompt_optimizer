Reference and fixed settings
-----------------------------
Start with the selected shared OpenBookQA Qwen configuration:
S=3, T=3, H=0.45, C=10, G=200, B=10, F=0.5.
S: maximum selected regions; T: maximum source tokens per region;
H: relative neighboring-gradient expansion threshold;
C: requested new replacements per region, plus the unchanged candidate;
G: correctness-balanced gradient subset; B: beam width;
F: fluency penalty, not the stable-score lambda.
Actual region lengths and valid candidate counts may be lower than requested.

Math random training pool: 1600 per source prompt; seed=42.
Target reasoning output limit: 8192; candidate/synthesis output limits: 10000.
Validation: deterministic 3 x 300 from the existing 3 x 500 file.
Stable-score lambda=1; no test runs.
Dual backend on the same logical GPU: vLLM ratio=0.4, HF device=cuda:0.
Reduced from 0.5 after attempt 1 ran out of memory during HF gradients.
The 1600 training responses and balanced subset were saved before the failure.
Default physical GPU=3; override using MATH_TUNING_GPU.
vLLM generates text; HF computes gradients, answer-token loss, and fluency.
Gradient and objective microbatches=1 for long reasoning inputs: memory
controls, not additional quality-tuning parameters.
Gold-answer loss is conditioned on generated reasoning and averaged across
answer tokens; generated reasoning is not supervised as a gold trace.
The fixed answer instruction remains uneditable. Synthesis is greedy and
uses the existing prompt-tag parsing; no synthesis fallback is added.

Caching and balance
-------------------
Each source has its own 1600-response cache. Identical source text can share
regardless of CODE/method; different source text cannot share responses.
LPO and all gradient refiners can reuse compatible larger pools. A smaller
request uses the requested prefix, while the full cache remains intact.
Keep pool=1600 across Math Qwen gradient methods for a controlled comparison;
LPO may request fewer examples, without requiring gradients or balancing.
Training source inference is greedy for all cache users; validation unchanged.
Balanced subsets use the shared seed and outcome IDs.
G=200 means up to 100 correct + 100 incorrect. If fewer failures exist, log and
use the largest balanced subset; do not claim that all 200 were used.
At roughly 90% accuracy, 1600 may give around 160 failures, but this is only an
estimate: inspect actual training counts and selected counts.
Only responses/subset selections/source-validation results are cached;
gradients and candidate HF objective scores are not cached as gradients.

Cost and interpretation
------------------------
Full final validation can generate up to 10 x 900 = 9000 responses per attempt,
plus source evaluation if uncached. Reasoning and HF candidate scoring are
expensive; benchmark the first attempt before forecasting total GPU hours.
No measured runtime exists for this new tuning script.
Beam scoring reuses source reasoning; fresh candidate reasoning is generated
in validation. Training-loss gains alone do not prove accuracy gains.
Record actual regions/text/lengths, valid replacements, bucket sizes, parsing
failures, stable/raw gains, token usage, and phase timings using existing
artifacts. Dedicated edit_tracking remains disabled.

and duplicate original EvoPrompt snapshots. Do not run them as this plan;
