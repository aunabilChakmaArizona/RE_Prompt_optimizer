OpenBookQA GradPO-Gen hyperparameter tuning
============================================

Purpose
-------
Tune GradPO-Gen separately for each target-model family using one fixed RPO-5
source prompt and the OpenBookQA non-reasoning 3 x 500 validation folds. Test
data are not used during tuning.

Validation score: mean accuracy - 1.0 x across-fold standard deviation

Both model families use an initial pool of 800 (Qwen) or 600 (Gemma), the same
G=200 correctness-balanced gradient subset, seed 42, and 1,500 validation
examples. GreaTer and GreaTer-TG retain the relation-extraction baseline
settings K=25, top-mu=10, fluency weight 0.2, and now evaluate top-u=10 prompts
on validation to match the GradPO beam width of 10.

GradPO-Prob and GradPO-Gen-Random use the selected shared model-specific
settings. Qwen uses S=3, T=3, H=0.45, C=10, G=200, B=10, F=0.50. Gemma uses
S=5, T=3, H=0.60, C=7, G=200, B=10, F=0.50. The random baseline changes only
region selection; its remaining generation, search, scoring, seed, and data
settings match GradPO-Gen. The Gemma matrix correctly uses actual RPO iteration
3 as the experimental RPO-5 source and iteration 4 retained through iteration
10 as the RPO-10 source.

LPO uses 512 training examples, three incorrect feedback examples, at most five
editable locations and three words per location, and one batch of ten rewrite
requests. It performs no retry. Every distinct non-empty parsed rewrite is
evaluated directly on validation; the source prompt is handled separately by
the shared source-validation cache.

This RPO-only matrix contains 20 runs: two models x two RPO source prompts x
five remaining second-stage methods. EvoPrompt and ETGPO were deferred when
this matrix was created; their active command matrices are documented below.
