STEP 2A -- Save paths and account in Bash once
----------------------------------------------
First confirm that your login shell is Bash and find the available Miniforge
module version:

If the shell is Bash, inspect ~/.bashrc for an existing similar block, then
open it with `nano ~/.bashrc` and add the block below ONCE. Use version 2.10.0:
NCSA documents it with CUDA 12.9, matching the cu129 wheels we will install.
The 2.11.0 module loads a CUDA 13.1 toolkit and is not our preferred Conda
initializer for this particular environment. Check the full `module spider`
output for any loading prerequisites. These lines must be SAVED IN ~/.bashrc, not
merely typed as temporary `export` commands in the terminal. In nano, press
Ctrl+O, Enter, then Ctrl+X to save and exit.
If the shell is not Bash, use its startup file instead; do not assume Bash's
~/.bashrc runs in a different shell.

# DeltaAI prompt-optimization setup: add once to ~/.bashrc.
export SLURM_ACCOUNT=bihn-dtai-gh
export PROJECT_DIR=/projects/bihn
export BASE_DIR="$PROJECT_DIR/$USER/promptopt"
export REPO_DIR="$BASE_DIR/RE_Prompt_optimizer"
export CONDA_ENV="$HOME/conda_envs/re_prompt_optimization_vllm_v2"
export CONDA_PKGS_DIRS="$HOME/conda_pkgs"
export PIP_CACHE_DIR="$HOME/pip_cache"
export HF_HOME="$BASE_DIR/huggingface_cache"
export CONDA_MODULE=python/miniforge3_pytorch/2.10.0
if command -v module >/dev/null 2>&1; then
  module load "$CONDA_MODULE"
fi
if command -v conda >/dev/null 2>&1; then
  export CONDA_SH="$(conda info --base)/etc/profile.d/conda.sh"
  source "$CONDA_SH"
fi

If you previously sourced ~/.bashrc with the 2.11.0 module, edit its module
line to 2.10.0 and start a FRESH SSH login after saving. Do not merely source
the edited file in the same shell: CUDA 13.1 variables/modules may remain
loaded. Otherwise, source the file once to load the block in this existing
Bash session. Future Bash logins should load it automatically. `echo` only
PRINTS values to verify them; you do not need `echo ... >> ~/.bashrc` after
using nano.

source ~/.bashrc  # only if this shell has not loaded the 2.11.0 module
echo "$SLURM_ACCOUNT"
echo "$PROJECT_DIR"
echo "$CONDA_ENV"
echo "$CONDA_MODULE"
module list

This configures the account, project paths, Conda path, and caches for future

BASE_DIR holds code, model weights, data, and results. The Conda environment
and Conda/pip package caches stay under HOME. Project files are not
automatically backed up; keep important results elsewhere too.

This may wait in the queue. Once it opens, you are on a COMPUTE node.
Reload/activate your environment if your shell startup changed it:

module load "$CONDA_MODULE"
source "$CONDA_SH"
conda activate "$CONDA_ENV"
# The site library path shadows the NCCL bundled with this PyTorch wheel.
# Clear it only for this compute-node shell, after loading the module/Conda.
unset LD_LIBRARY_PATH
cd "$REPO_DIR"
nvidia-smi

python -c 'import torch; assert torch.cuda.is_available(), "CUDA unavailable"; print(torch.__version__, torch.version.cuda); print(torch.cuda.get_device_name(0)); x=torch.ones(4, device="cuda:0"); print(x.sum().item())'
python -c 'import torch; from vllm import _C; print("vLLM CUDA extension import OK")'

Expect a working GPU and tensor sum4.0. These are basic checks, not proof
that Gemma generation, gradients, and prompt-logprob scoring all work.
On DeltaAI, leaving LD_LIBRARY_PATH set to the site module's value can make
`import torch` fail with `undefined symbol: ncclCommWindowRegister`. This
environment bundles its own NCCL; keep `unset LD_LIBRARY_PATH` after
`conda activate` in Slurm jobs too, not in ~/.bashrc.
Slurm owns CUDA_VISIBLE_DEVICES. Do NOT set it to physical GPU3/1/etc.
Our code uses cuda:0 INSIDE the GPU assigned to this job.

When finished, release the interactive allocation and return to the login node:

exit

GPU memory is NOT the --mem value. Both HF/vLLM copies share the assigned GPU,
with vLLM ratio0.50 and gradient microbatch1. Actual peaks must be checked.

If something fails
------------------
- SSH failure: confirm NCSA username/password and NCSA Duo enrollment.
- accounts empty/access denied: contact NCSA about allocation membership.
- Missing script/scorer: latest LOCAL changes were not uploaded to GitHub.
- Missing data: extract promptopt_data.zip in the repository root.
- No matching ARM wheel: save pip output; do not switch blindly to newer pins.
- CUDA unavailable on LOGIN node: normal; repeat on a Slurm COMPUTE node.
- CUDA unavailable on COMPUTE node or extension import fails: stop; save
  uname -m, nvidia-smi, pip check, package versions, and full traceback.
- Gemma403: accept model terms and use a token for the approved HF account.
- GPU OOM: save the error; consider ratio0.40 without shrinking G/validation:
  MATH_TUNING_VLLM_RATIO=0.40 MATH_TUNING_START=FAILED_ATTEMPT sbatch \
    --account="$SLURM_ACCOUNT" --partition=ghx4 \
    codes/run_math_gradpo_tuning_gemma.slurm
  This still reruns the failed attempt from its beginning, using valid caches.
- A job pending is not necessarily broken: inspect squeue/scontrol reasons.
