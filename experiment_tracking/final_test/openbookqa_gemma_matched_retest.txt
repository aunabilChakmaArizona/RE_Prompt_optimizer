Gemma OpenBookQA matched-setting retest
=====================================
Script: codes/run_openbookqa_gemma_matched_test.sh
Purpose: compare fresh solo-initial and batched-initial generation, and rerun
all selected first-/second-stage prompts without replacing historical results.
This is an execution diagnostic, not further test-based prompt selection.

Shared settings
---------------
google/gemma-3-4b-it; vLLM; GPU 3 by default; memory utilization 0.8;
16 output tokens; images allowed (no --vllm-disable-images); base seed 42;
temperature 1.0, top_p 0.95, top_k 64; unchanged static answer instruction;
strict tagged-answer grading; official 500-question test; one decoding run.
Solo uses the model-native context limit, recorded as 131072 in its earlier
log. Batch explicitly sets that same 131072 limit. Check both startup logs
confirm this and identical runtime settings before interpreting differences.
Each command creates a fresh engine; queue size remains deliberately different.
No eager/prefix-cache overrides or new inference implementation are introduced.
The former image-disabled/10-token batch configuration is not reproduced here.

Separate output identities
--------------------------
RUN_TAG defaults to a UTC timestamp and can be set explicitly.
Solo CODE: openbookqa_non_reasoning_gemma_initial_matched16_<RUN_TAG>
Batch CODE: openbookqa_non_reasoning_gemma_selected_matched16_<RUN_TAG>
Solo directory: outputs/qa_final_test/non_reasoning/final_test/<SOLO_CODE>/
Batch directory: outputs/qa_final_test/non_reasoning/selected_prompts/<BATCH_CODE>/
The batch results.txt includes all 36 scores, source-relative gains, provenance,
missing-tag counts, and predictions-file paths. config.json records settings.
No --overwrite: existing CODEs are protected; choose a new RUN_TAG to repeat.
Historical aggregate reports are not regenerated by this script.

Interpretation
--------------
Compare fresh solo and fresh batched initial raw outputs, formatting failures,
and accuracy first. Similar seeds do not guarantee identical sampled outputs.
Do not mix these 16-token scores with the old 10-token table when claiming gains.
Do not substitute diagnostic bare-letter accuracy for strict tagged accuracy.
If the batch initial remains abnormal, isolate engine flags/order separately
before accepting initial-to-optimized improvements. No GPU runs were launched
when preparing this script.
